Natural Language Processing (NLP) Pipeline

Computers cannot understand raw text directly; they only understand numbers. To prepare our email text for training, we pass it through an NLP pipeline that strips noise and transforms it into numerical vectors.

Step 1: Lowercasing & Cleaning

Convert all letters to lowercase to ensure consistency (so "FREE" and "free" match). We use regex to drop numbers, emojis, and special characters (like $, !, %), leaving only alphabet words.

Step 2: Tokenization

Using NLTK's tokenizers, we slice the text string into individual strings of words. For example: "Save money today" becomes a Python list: ["save", "money", "today"].

Step 3: Stop Words Removal

Stop words (like "the", "is", "at", "which") are highly frequent words in English that carry no discriminative meaning. Removing them keeps only context-heavy words (like "prize", "cash", "lottery").

Step 4: Lemmatization

Reduces words to their core dictionary form (lemma) using linguistic rules. For instance, "running", "runs", and "ran" all compress to "run". This is cleaner than Stemming, which simply truncates endings (e.g. "studying" -> "studi").

What is TF-IDF?

TF-IDF stands for Term Frequency-Inverse Document Frequency. It computes the weight of a word:
1. Term Frequency (TF): How often does the word appear in this message? (High frequency = higher importance).
2. Inverse Document Frequency (IDF): How common is this word across all emails? If a word is in every single message, its IDF drops to zero (because it doesn't help distinguish spam from safe emails).
This converts our text into a sparse table of numeric weights.

Model Selection & Comparison

We trained two algorithms to learn the boundaries between Spam and Ham messages. Here is why they are chosen:

Multinomial Naive Bayes

Based on **Bayes' Theorem** of conditional probability. It calculates the probability of a message being "Spam" given the words inside it.

Bayesian Probability
  • Assumption: Word occurrences are conditionally independent of each other (the "Naive" part).
  • Strength: Extremely fast to train, works very well on text count/frequency matrices, and uses low RAM.
  • Weakness: Ignores word order or phrase context.
Logistic Regression

A classification algorithm that fits a **Sigmoid S-curve** to predict binary label probabilities (values bounded between 0 and 1).

Sigmoid Optimization
  • Concept: Learns continuous coefficients for TF-IDF feature variables and transforms linear output using: 1 / (1 + e^-z).
  • Strength: Highly robust, less prone to overfitting on text features, and outputs calibrated class probabilities.
  • Weakness: Struggles to learn non-linear relationships.

Future Scaling & Improvements

How could you improve this system for industrial, real-world deployment?

  • Deep Learning Models: Replace TF-IDF + Logistic Regression with sequence models like **LSTM** or pre-trained transformer embeddings like **BERT** to capture semantic contexts and sequence structures in text.
  • Background Task Queue: Instead of running predictions synchronously within the HTTP thread, use task workers like **Celery & Redis** to handle massive volumes asynchronously and prevent request timeouts.
  • REST API Interface: Implement **Django REST Framework (DRF)** to enable third-party email clients or plugins (like Outlook or Gmail Add-ins) to communicate with our model endpoints.
  • Feedback Loop: Add a "Report Correction" button in the frontend. When users report a misclassification, log it to a feedback queue to periodically re-train and fine-tune models.
